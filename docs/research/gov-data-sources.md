# 気象庁・厚労省・国交省 データソース調査 (#304)

city-score の指標（気候ストレス / キャリア持続性 / 人生コスト効率 / 老後就労 等）に用いる、e-Stat 以外の日本政府系データソースの取得方法・更新頻度・欠損リスクをまとめる。

> 記載は一般に公知の仕様レベル。エンドポイント・提供形式は変更され得るため「要検証」項目を参照。

## 1. 気象庁 (JMA)

### 1.1 主なデータ

| データ                                  | 用途（city-score）                           | 提供形式         | 取得方法                                                                                              |
| --------------------------------------- | -------------------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------- |
| 過去の気象データ（アメダス / 気象官署） | 気候ストレス（気温・降水・日照・積雪・湿度） | CSV ダウンロード | 「過去の気象データ・ダウンロード」画面から地点・期間・要素を指定して CSV 取得                         |
| 平年値（1991–2020 等の 30 年平均）      | 気候ストレスの基準値・偏差算出               | CSV / Web 表     | 気象庁「平年値」ページ                                                                                |
| 天気予報・防災情報 JSON                 | （将来）リアルタイム系                       | JSON             | `https://www.jma.go.jp/bosai/forecast/data/forecast/<area_code>.json`（**非公式・予告なく変更あり**） |

### 1.2 取得方法・注意

- **公式 API は限定的**。予報・防災系の JSON エンドポイント（`bosai`）は Web サイト用で、公式に「API」として保証されたものではない。**要検証 / 変更リスク高**。
- 過去観測値の一括取得は「過去の気象データ・ダウンロード」の CSV が実用的。地点コード（観測所番号）と要素を指定。
- city-score 用途では**平年値ベースの気候ストレス**が中心のため、リアルタイム性は不要 → CSV 一括取得で十分。

### 1.3 更新頻度

- 観測値: 日次更新（過去データは確定後）。city-score では年 1 回程度の再取得で足りる。
- 平年値: 10 年ごとに更新（例: 1991–2020）。

### 1.4 欠損リスク

- 観測所の**地点粒度 ≠ 市区町村**。アメダス地点を市区町村へ最近傍 / 内挿でマッピングする必要（→ 欠損・誤差要因）。**要検証**（マッピング手法）。
- 観測所の新設・廃止・移設により長期時系列に断絶。
- 山間部・離島は近傍観測所が遠く精度低下。

## 2. 厚生労働省 (MHLW)

### 2.1 主なデータ

| データ                               | 用途                                         | 提供形式                           | 取得方法                                                       |
| ------------------------------------ | -------------------------------------------- | ---------------------------------- | -------------------------------------------------------------- |
| 一般職業紹介状況（有効求人倍率）     | キャリア持続性・老後就労（雇用の厚み）       | e-Stat / MHLW サイト（Excel・CSV） | 都道府県別が基本。市区町村粒度は**ハローワーク管轄単位**で別途 |
| 賃金構造基本統計調査                 | 人生コスト効率（所得水準・年齢別賃金カーブ） | e-Stat（統計表）                   | e-Stat API 経由取得が容易                                      |
| 介護・医療提供体制（施設数・病床数） | 老後就労 / 社会的孤立（インフラ）            | e-Stat・厚労省公開データ           | 都道府県 / 二次医療圏単位が多い                                |
| 高年齢者雇用状況等報告               | 老後就労（高齢者雇用機会）                   | 厚労省サイト（集計表）             | 主に都道府県単位                                               |

### 2.2 取得方法・注意

- 厚労省統計の多くは **e-Stat に収録**されており、`#303` の e-Stat API 経由取得が第一選択。
- 有効求人倍率の**市区町村粒度は存在しない**（ハローワーク管轄 or 都道府県が最小）。city-score では都道府県値を市区町村へ按分 or 継承する近似が必要。**要検証**（按分方法）。

### 2.3 更新頻度

- 有効求人倍率: 月次（速報）。city-score では年平均を使用。
- 賃金構造基本統計調査: 年次。
- 医療・介護提供体制: 年次〜数年。

### 2.4 欠損リスク

- 粒度不整合（都道府県／医療圏 → 市区町村）が最大リスク。
- 小規模市区町村では標本不足による非公表・秘匿。

## 3. 国土交通省 (MLIT)

### 3.1 主なデータ

| データ                                                      | 用途                                                         | 提供形式                              | 取得方法                                                                      |
| ----------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------- | ----------------------------------------------------------------------------- |
| 不動産情報ライブラリ / 不動産取引価格情報                   | 人生コスト効率（住居費）                                     | Web API / CSV                         | 「不動産情報ライブラリ API」（要 API キー、旧「土地総合情報システム」を統合） |
| 国土数値情報（駅・バス停・医療・学校・避難所・地価公示 等） | 社会的孤立（アクセス性）・気候ストレス（災害）・移住者受容度 | GML / Shapefile / GeoJSON             | 「国土数値情報ダウンロードサイト」から都道府県・年度別に取得                  |
| 地価公示・地価調査                                          | 人生コスト効率（地価）                                       | 国土数値情報 / API                    | 地点ポイントデータ                                                            |
| ハザード関連（浸水想定・土砂災害警戒区域 等）               | 気候ストレス（災害リスク）                                   | 国土数値情報 / ハザードマップポータル | GIS データ                                                                    |

### 3.2 取得方法・注意

- **不動産情報ライブラリ API**: API キー発行が必要（MLIT のサイトで申請）。取引価格・地価・都市計画等を提供。**要検証**（キー取得手順・レート制限・エンドポイント最新形）。
- **国土数値情報**: GIS フォーマット（GML/Shapefile/GeoJSON）。市区町村コードに紐づく、または座標点データ。GIS 前処理（空間結合で市区町村へ集約）が必要 → 処理コスト大。
- city-score では初期フェーズは「点データを市区町村ポリゴンに空間結合して件数/密度化」する方針。**要検証**（前処理パイプライン）。

### 3.3 更新頻度

- 不動産取引価格: 四半期更新。
- 地価公示: 年 1 回（例年 3 月公表）。
- 国土数値情報: データ種別ごとに年度更新（更新されない静的データもあり）。

### 3.4 欠損リスク

- 取引価格は**実取引の集計**のため、取引の少ない地方部でサンプル希薄・欠損。
- GIS データの年度が種別間で不揃い → 時点整合の困難。
- 座標→市区町村マッピングの精度（境界付近）。

## 4. 横断的な留意点

- **粒度統一**: 全ソースを「市区町村（5 桁 JIS コード） × 年」に正規化するのが city-score の中核作業。都道府県・医療圏・観測所粒度は按分/継承/空間結合で近似し、近似手法を欠損メタとして記録する。
- **出典表記**: 各成果物に出典明記（政府標準利用規約準拠）。
- **キャッシュ**: すべてローカルキャッシュ。API/CSV は年次バッチ。

## 5. 要検証項目（まとめ）

- [ ] アメダス地点 → 市区町村マッピング手法（最近傍 / 内挿 / 面積按分）。**要検証**。
- [ ] 有効求人倍率・医療圏データの市区町村按分方法。**要検証**。
- [ ] MLIT 不動産情報ライブラリ API のキー取得手順・レート制限・最新エンドポイント。**要検証**。
- [ ] 国土数値情報の各種別の最新年度と GIS 前処理コスト。**要検証**。
