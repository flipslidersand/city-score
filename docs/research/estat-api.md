# e-Stat API 仕様調査 (#303)

政府統計の総合窓口 e-Stat が提供する「API 機能」を、city-score の市区町村別データ取得基盤として利用するための調査メモ。

> 記載内容は一般に公知の仕様レベルに基づく。実運用前に最新の [API 利用ガイド](https://www.e-stat.go.jp/api/) で再確認すること（末尾「要検証」項目を参照）。

## 1. 概要

- 提供元: 総務省統計局 / 独立行政法人統計センター
- サービス名: 政府統計の総合窓口 (e-Stat) API 機能
- 公式ドキュメント: https://www.e-stat.go.jp/api/
- 現行メジャーバージョン: **3.0**（`https://api.e-stat.go.jp/rest/3.0/app/...`）
- 提供形式: REST。レスポンス形式は XML / JSON / JSONP / CSV を選択可能。

## 2. 認証方式

- **アプリケーション ID（appId）方式**。OAuth ではなく、発行された文字列トークンを各リクエストのクエリパラメータ `appId` に付与する。
- 取得手順:
  1. e-Stat のユーザー登録（メールアドレスで無料登録）。
  2. マイページの「API 機能（アプリケーション ID 発行）」からアプリケーションを登録。
     - 登録時に「名称」と「URL」（利用アプリの URL、開発中はダミー可）を入力。
  3. 発行された appId（英数字トークン）を控える。1 ユーザーで複数 appId 発行可能。
- **秘匿性**: appId は URL クエリに露出するため秘密鍵ほど厳格ではないが、city-score では `.env` / Vault で管理し、コミットしない（Platform ルール準拠）。
- 利用規約: 政府標準利用規約（第 2.0 版）準拠。出典明記が必要（例:「出典: 政府統計の総合窓口 (e-Stat)」）。商用利用可。

## 3. レート制限・制約

| 項目                           | 内容                                 | 備考                                                                |
| ------------------------------ | ------------------------------------ | ------------------------------------------------------------------- |
| 1 リクエストあたり取得件数上限 | 10 万件（`getStatsData` の `limit`） | 超える場合は `startPosition` でページング                           |
| 同時／連続アクセス             | 明示的な RPS 上限は公表されていない  | **要検証**: 過度な連続アクセスは避け、スリープ挿入 + キャッシュ推奨 |
| appId 発行数                   | 1 ユーザー複数可                     | 用途別に分離可能                                                    |

city-score 方針: 取得済みデータはローカル（SQLite / CSV）にキャッシュし、更新頻度（年次が大半）に合わせてバッチ取得。リアルタイム呼び出しはしない。

## 4. 主要エンドポイント（v3.0）

ベース URL: `https://api.e-stat.go.jp/rest/3.0/app/`（JSON 版は `.../app/json/`）

| 機能                   | エンドポイント   | 用途                                           |
| ---------------------- | ---------------- | ---------------------------------------------- |
| 統計表情報取得         | `getStatsList`   | 利用可能な統計表 ID (`statsDataId`) を検索     |
| メタ情報取得           | `getMetaInfo`    | 表の分類項目（地域・時間・カテゴリ）定義を取得 |
| 統計データ取得         | `getStatsData`   | 実データ本体を取得                             |
| データセット登録       | `postDataset`    | 抽出条件を保存（任意）                         |
| データセット参照       | `refDataset`     | 保存条件でデータ取得（任意）                   |
| データカタログ情報取得 | `getDataCatalog` | ファイル（Excel/CSV）ベースのカタログ検索      |

### 4.1 リクエスト例（統計データ取得, JSON）

```
GET https://api.e-stat.go.jp/rest/3.0/app/json/getStatsData
  ?appId=<APP_ID>
  &statsDataId=<統計表ID>
  &cdArea=<地域コード>        # 市区町村: 5桁 JIS コード（例 13101=千代田区）
  &cdCat01=<分類コード>
  &startPosition=1
  &limit=100000
  &metaGetFlg=Y              # メタ情報同梱
  &cntGetFlg=N
```

主なパラメータ:

- `statsDataId`（必須）: 統計表 ID。`getStatsList` で検索して得る。
- `cdArea` / `cdAreaFrom` / `cdAreaTo`: 地域コードによる絞り込み。カンマ区切りで複数指定可。
- `cdTime` / `cdTimeFrom` / `cdTimeTo`: 時間軸（年次・月次）の絞り込み。
- `cdCat01`〜`cdCat15`: 分類事項の絞り込み。
- `lang`: `J`（日本語）/ `E`（英語）。

### 4.2 レスポンス構造（JSON, getStatsData 抜粋）

```
GET_STATS_DATA
 └ STATISTICAL_DATA
    ├ RESULT_INF        # 取得件数・次ページ位置(NEXT_KEY)
    ├ TABLE_INF         # 統計表メタ
    ├ CLASS_INF         # 分類定義（CLASS_OBJ[].CLASS[] = コード⇔名称対応表）
    └ DATA_INF
       └ VALUE[]        # 実値。@area,@time,@cat01,@unit,$=値
```

- 値は `VALUE` 配列。地域・時間・分類は**コード**で入るため、`CLASS_INF` の対応表で名称解決が必要。
- 欠損・秘匿値: `$` が数値でなく記号（例: 秘匿を表す `-`, `***`, `X` 等）になる場合がある。**パース時に数値変換失敗をハンドリングし欠損として扱う**。

## 5. 市区町村別データの取得方法

1. **地域コード体系**: e-Stat は「標準地域コード（JIS X 0402、5 桁）」を採用。都道府県 2 桁 + 市区町村 3 桁。政令市の区は独自コードあり。
   - 対応表は e-Stat の「地域コード」ページ、または `getMetaInfo` の地域 `CLASS_OBJ` から取得可能。
2. **市区町村粒度を持つ統計表を選ぶ**:
   - 「市区町村データ（社会・人口統計体系）」= 市区町村別に多数の基礎指標を横断収録した統計表群。city-score の主力候補。
   - 「国勢調査」小地域・市区町村集計。
   - 「経済センサス」市区町村別。
3. **取得フロー（バッチ）**:
   1. `getStatsList` で目的の `statsDataId` を特定（用途別に台帳化 → `docs/data-catalog.md`）。
   2. `getMetaInfo` で地域・分類コードを取得しローカルに保存。
   3. `getStatsData` を `cdArea` 全市区町村 or 未指定（全件）+ `startPosition` ページングで取得。
   4. コード→名称解決後、正規化テーブル（長形式: area_code, year, indicator, value）に格納。

## 6. city-score での利用方針まとめ

- appId は環境変数管理・非コミット。
- 取得は年次バッチ + ローカルキャッシュ。API を直接ホットパスに置かない。
- 欠損／秘匿値の正規化ルールを共通化（→ `docs/data-catalog.md` の欠損率列と連動）。
- 出典表記を成果物に必ず付す。
